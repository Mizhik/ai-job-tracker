# AI Job Tracker Frontend

React + TypeScript + Vite веб-інтерфейс для проєкту AI Job Tracker.

> **Stage 07.4 — Створення збережених вакансій та фінальна інтеграція:** Реалізовано форму створення нової збереженої вакансії (`POST /jobs`), повну перевірку введених даних на клієнті та обробку помилок сервера, а також підтримку першого сценарію користувача (first-user flow) та збереження даних після перезавантаження сторінки.

## Функціональність перегляду, пошуку та створення вакансій (Stage 07)

- **Створення вакансії (`POST /jobs`):** Форма `CreateJobForm` дозволяє авторизованому користувачу додавати нові вакансії зі створенням запису на сервері. Кнопка створення доступна як з верхньої панелі списку, так і з порожнього стану для нових користувачів.
- **Валідація та перевірка даних:**
  - Обов’язкові поля: `title` (назва вакансії) та `company` (компанія) не можуть бути порожніми.
  - Зарплатні межі: `salary_min` та `salary_max` повинні бути невід’ємними цілими числами, причому `salary_min` <= `salary_max`.
  - Валюта та період: при вказівці числової зарплати обов’язково вимагаються код валюти (3 латинські літери, наприклад USD, EUR, UAH) та період оплати (`hour`, `month`, `year`). Якщо числова зарплата відсутня, валюта та період залишаються `null`. Код валюти валідується завжди при його вказівці.
  - Джерело: `source_url`, якщо вказано, має містити коректне `http://` або `https://` посилання.
  - Технології: текстове поле розділяється за комами у масив рядків (`string[]`).
- **Обробка помилок та запобігання дублюванню:**
  - При помилці відправки всі введені користувачем дані зберігаються у формі для виправлення або повторної спроби.
  - Під час виконання запиту форма блокується для запобігання повторному відправленню (double submission).
  - При успішному створенні пошуковий фільтр та пагінація скидаються, щоб при поверненні зі сторінки деталей вакансія відображалася в загальному списку.
- **Список вакансій (`GET /jobs`):** Завантажує збережені вакансії авторизованого користувача з підтримкою параметрів пошуку `q`, пагінації (`limit`, `offset`).
- **Пошук:** Форма пошуку дозволяє фільтрувати вакансії за назвою або компанією. При порожньому результаті пошуку відображається відповідний стан із можливістю скидання фільтра.
- **Деталі вакансії (`GET /jobs/{job_id}`):** При виборі вакансії відкривається її повна картка з описом, розміром заробітної плати, джерелом, списком технологій та можливістю повернутися до списку.
- **Навігація та стани:** Підтримуються стани завантаження (`LoadingState`), помилок запитів з кнопкою повтору (`ErrorState`), а також порожні стани (`EmptyState`) для нових користувачів.

## Архітектура авторизації

- **Access Token:** Зберігається тільки в оперативній пам'яті (`ApiClient` / `AuthContext`), ніколи не зберігається в `localStorage` чи `sessionStorage`.
- **Сесія та Refresh Cookie:** Сервер встановлює HttpOnly cookie для оновлення токена.
- **Відновлення сесії:** При перезавантаженні сторінки клієнт робить `GET /users/csrf`, отримує CSRF-токен, викликає `POST /users/refresh` із заголовком `X-CSRF-Token`, та запитує дані профілю `GET /users/me`.
- **Автоматичне оновлення токена:** При виконанні захищених запитів і отриманні `401 Unauthorized`, клієнт автоматично виконує single-flight оновлення токена та повторює оригінальний запит (щонайбільше один раз).
- **Вихід із системи:** Виклик `POST /users/logout` з CSRF-токеном анулює сесію на сервері та очищає локальний стан авторизації.

## Локальна розробка та Vite Dev Proxy

Vite налаштовано на проксіювання маршрутів `/users` та `/jobs` на бекенд. За замовчуванням цільова адреса бекенду — `http://localhost:8000`.

Для зміни адреси бекенду створити файл `.env.local` у папці `frontend/`:

```env
VITE_BACKEND_TARGET=http://localhost:8000
```
